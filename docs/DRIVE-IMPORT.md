# Загрузка выгрузки Apple Health из Google Drive

## Задача

Выгрузка Apple Health кладётся в общую папку Google Drive. Сервис должен сам —
раз в сутки в заданное время или по кнопке — сходить в эту папку, забрать
свежий файл и догрузить то, чего в базе ещё нет.

Раньше выгрузку клали в каталог рядом с сервисом и запускали загрузку руками.
Каталог никуда не девается: Drive — второй источник того же файла, а не замена
всему устройству импорта.

## Почему не Telegram

Первым подходом был бот в закрытой группе. Он не годится: Bot API не отдаёт
боту файл больше 20 МБ, а выгрузка — три гигабайта на диске и сотни мегабайт в
архиве. Обходные пути (свой сервер Bot API, резка архива на части) стоят дороже,
чем ссылка на папку.

У Drive этого ограничения нет: файл отдаётся потоком любого размера.

## Устройство

```
   Google Drive (публичная папка)
            │  files.list + files.get?alt=media, ключ API
            ▼
   ┌──────────────────┐   свежий файл?      ┌────────────────┐
   │  DriveClient     │──────────────────▶ │  DriveService  │
   │  ссылка → id     │   метаданные,      │  что делать    │
   │  список, скачать │   контрольная сумма└───────┬────────┘
   └──────────────────┘                            │
                                        скачать в кэш, распаковать
                                                   │
                                                   ▼
                                      ┌───────────────────────┐
                                      │  AppleHealthService   │
                                      │  разбор и свёртка     │
                                      │  (уже существует)     │
                                      └───────────────────────┘
```

Модуль отдельный — `apps/api/src/modules/drive/`. Он ничего не знает о разборе
XML: его дело довести файл до диска и позвать существующий импорт. Импорт, в
свою очередь, ничего не знает о Drive.

### Части

| файл | ответственность |
|---|---|
| `drive-link.ts` | разбор ссылки: папка это или файл, какой идентификатор |
| `drive-client.ts` | Drive API v3: список папки, метаданные, скачивание потоком |
| `drive-archive.ts` | распаковка zip и опознание выгрузки Apple Health |
| `drive.service.ts` | что делать: сравнить, скачать, распаковать, запустить импорт |
| `drive.schedule.ts` | ежедневная проверка в заданное время |
| `drive.controller.ts` | настройки, кнопка «Загрузить», журнал проверок |

### Чем открывается папка

Способа два, и они не равны.

**Сервисный аккаунт** (`GOOGLE_SERVICE_ACCOUNT_FILE`) — отдельный пользователь
Google со своей почтой. Папку открывают **ему одному**, и для остального мира
она остаётся закрытой. Для истории здоровья это существенно, поэтому способ
предпочтительный. Сервис просит единственное право —
`drive.readonly`, — и подписывает запрос токена сам: `googleapis` тянет
полсотни мегабайт зависимостей ради одного обмена JWT на токен.

**Ключ API** (`GOOGLE_API_KEY`) — запасной путь. Он открывает только то, что и
так открыто по ссылке, то есть папку приходится держать публичной.

Если задано и то, и другое, выигрывает сервисный аккаунт. Нет ни того, ни
другого — модуль не падает, а честно говорит, что не настроен, и пишет в
интерфейсе, какой из способов сейчас работает.

Оба ключа лежат в `.env` и `secrets/` и в репозиторий не едут. Путь к файлу
ключа считается от каталога запуска: в разработке это `apps/api`, поэтому в
`.env` он записан как `../../secrets/service-account.json`; в контейнере каталог
смонтирован в `/app/secrets`, и путь задан абсолютным.

**Что нужно сделать один раз.** Для сервисного аккаунта: включить Drive API в
том проекте Google Cloud, которому принадлежит аккаунт, и открыть папку на его
почту (`…@….iam.gserviceaccount.com`) с правом просмотра. Для ключа API:
создать ключ в Cloud Console и сделать папку доступной по ссылке.

### Что считается выгрузкой

Проверяется содержимое, а не имя. Годятся:

- `.zip`, внутри которого есть `apple_health_export/экспорт.xml` или
  `apple_health_export/export.xml`;
- `.xml`, начинающийся с `<HealthData` и содержащий `HKCharacteristicType`.

Всё остальное отклоняется с объяснением в журнале: чужой файл в общей папке —
обычное дело, и падать на нём нельзя.

Имена записей читаются как UTF-8 вручную. iOS кладёт `экспорт.xml` в UTF-8, но
не выставляет в записи флаг UTF-8; по стандарту это значит CP437, и честный
читатель получает `╤ì╨║╤ü╨┐╨╛╤Ç╤é.xml`. На живой выгрузке это выглядело как
«в архиве нет файла выгрузки».

### Когда файл считается новым

Drive отдаёт `md5Checksum`, `size` и `modifiedTime`. Сервис помнит их с
последней удачной загрузки. Совпало — загрузка пропускается, в журнал пишется
«тот же файл». Это и есть «догрузить только то, чего не было»: сама выгрузка
всегда полная, а повторный разбор двух гигабайт ради нуля новых дней —
двадцать секунд впустую.

Полный повторный разбор — намеренно (D-020): файл выгрузки источник правды,
база хранит свёртку. Свежая выгрузка содержит всю историю, включая новые дни.

### Куда скачивается

В `storage/health/` — на том же томе, что и собранные выгрузки. Каталог
пользователя (`HEALTH_DIR`) остаётся смонтированным **только на чтение**: туда
кладут руками, сервис оттуда только читает.

Из архива распаковывается один файл — основной XML. Клинический `export_cda.xml`
и маршруты тренировок не нужны и занимают больше гигабайта.

### Расписание

Время задаётся в интерфейсе строкой `ЧЧ:ММ` и хранится в аккаунте. Задача одна
на все аккаунты, просыпается каждую минуту и смотрит, чьё время настало —
общая часть с синхронизацией YAZIO вынесена в `common/daily-at.ts` (D-063).
Пустое время выключает проверку.

Фоновые расписания целиком выключаются переменной `SCHEDULES_ENABLED`. На
develop она `false`: база там — копия рабочей, с теми же настройками аккаунтов,
и второй экземпляр качал бы ту же выгрузку за теми же данными.

## Настройки в интерфейсе

Раздел «Синхронизация», карточка «Google Drive»:

- ссылка на папку или файл;
- время ежедневной проверки;
- переключатель «проверять ежедневно»;
- кнопка «Загрузить» — проверить прямо сейчас;
- журнал последних проверок: когда, что нашли, что сделали.

## Чего модуль не делает

- не ходит в приватные папки: только то, что открыто по ссылке;
- не пишет в Drive ничего и не удаляет;
- не разбирает выгрузку сам — этим занимается существующий импорт;
- не догружает «разницу» в смысле дельты: выгрузка всегда полная, и повторный
  импорт заменяет свёртку целиком.
