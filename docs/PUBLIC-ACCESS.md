# Публичный вход: https://<ваш-домен>

Сервис остаётся локальным — он как крутился в докере на домашней машине, так и
крутится. Появилась только дверь снаружи: адрес в своём домене, за которым стоит
проверка личности, и открыть её можно с телефона, где никакого VPN нет.

Устройство подхода, разбор безопасности и порядок для других проектов —
в [общем руководстве](../../docs/cloudflare-tunnel/setup-guide.md). Здесь только
то, что относится к fatoff.

## Как это выглядит снаружи

```
браузер ──https──▶ Cloudflare ──туннель──▶ fatoff-cloudflared ──fatoff-net──▶ fatoff-app:4090
                   │
                   └── Access: код на почту. Не прошёл — до сервиса не доехал
```

Заходящий вводит почту, получает код письмом, попадает на страницу входа
fatoff и вводит `APP_PASSWORD`. Два рубежа держатся на разном: почта и пароль.

## Что где лежит

| Что | Где | В репозитории? |
|---|---|---|
| Настройка туннеля | `infrastructure/cloudflared/config.yml` | **нет**: в ней адрес и идентификатор |
| Образец настройки | `infrastructure/cloudflared/config.example.yml` | да |
| Запуск | `infrastructure/cloudflared/docker-compose.yml` | да |
| Ключи туннеля | `~/.cloudflared/<идентификатор-туннеля>.json` | **нет, и не должно быть** |
| Сертификат управления зоной | `~/.cloudflared/cert.pem` | **нет** |
| Кого пускать | Cloudflare Zero Trust → Access → Applications | — |

Свой `config.yml` заводится из образца — один раз при разворачивании:

```bash
cp infrastructure/cloudflared/config.example.yml infrastructure/cloudflared/config.yml
# подставить адрес и идентификатор своего туннеля
```

Почему настоящий конфиг вне репозитория: адрес сервиса, идентификатор туннеля и
адрес страницы входа — опознаватели конкретной установки. Войти по ним нельзя,
но репозиторий публичный, и сообщать всем точный адрес личного сервиса с
историей здоровья незачем (D-062). Ключи туннеля и подавно: они лежат в
`~/.cloudflared` под правами хозяина машины и монтируются в контейнер только на
чтение.

Туннель ходит в `fatoff-app` по сети `fatoff-net`, минуя хост. Публиковать порт
приложения наружу для этого не нужно вовсе.

## Команды

```bash
pnpm tunnel:up      # открыть публичный вход
pnpm tunnel:down    # закрыть; локальный сервис продолжает работать
pnpm tunnel:logs    # что с соединением
```

Проверка, что дверь заперта, — одна, и делать её надо после каждой правки
политики доступа:

```bash
curl -sI https://<ваш-домен>/ | head -3
```

Ответ обязан быть `302` на `…cloudflareaccess.com`. Если пришёл `200` со
страницей fatoff — гейта нет, дневник открыт интернету: `pnpm tunnel:down` и
разбираться.

## Кого пускать

Zero Trust → Access → Applications → `FatOff` → политика → `Include → Emails`.
Добавление и удаление действуют сразу, перезапускать ничего не нужно.

## Что это значит для данных

Cloudflare терминирует TLS, то есть **видит содержимое в открытом виде** — весь
дневник питания и выгрузку здоровья, пока они едут в браузер. Это неизбежная
цена доступа с любого устройства без VPN, и на неё пошли сознательно: иначе
пришлось бы держать VPN-клиент на каждом телефоне.

Инвариант «экспорт не ходит в сеть» (D-010) это не нарушает: наружу по-прежнему
ничего не отправляется, речь только о канале до браузера хозяина.

## Чего ждать от Cloudflare

- **Запрос дольше 100 секунд обрывается** ошибкой 524. Сборка файла выгрузки
  (`POST /accounts/:id/exports`) идёт синхронно, в одном запросе, — на большом
  периоде это выстрелит. Файл при этом достроится и появится в списке, но
  браузер покажет ошибку. Лечится переводом на `202` + опрос, как у
  синхронизации.
- **Загрузка файла больше 100 МБ не пройдёт.** Для fatoff это неважно: выгрузка
  Apple Health и так забирается с диска и из Google Drive (D-060), а не через
  форму.

## Состояние

Работает с 29 августа 2026 года.

| Что | Значение |
|---|---|
| Адрес | https://<ваш-домен> |
| Туннель | `fatoff`, `<идентификатор-туннеля>` |
| Страница входа | `<ваш-домен>.cloudflareaccess.com` |
| Кого пускает | политика `Owners` — список адресов живёт в дашборде, не здесь |
| Способ входа | одноразовый код на почту, сессия месяц |

Проверено: анонимный запрос снаружи получает `302` на страницу входа Cloudflare
и до сервиса не доходит; туннель держит четыре соединения и видит `fatoff-app`
по внутренней сети.

Почему решение принято именно такое и что рассматривалось взамен — D-061 в
[журнале решений](DECISIONS.md).
