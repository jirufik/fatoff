# FatOff — памятка для будущих сессий

Сервис выгружает аккаунт YAZIO в свою базу и собирает из накопленного файлы для
анализа языковой моделью. Локальный, за паролем, в докере.

## Стек

Тот же, что в `dynamic-competitor` и `family-calendar`:

- pnpm 10 + Turborepo, Node 22.22.0
- NestJS 11 (Express, CommonJS), MikroORM 6 (**не TypeORM**), PostgreSQL 17
- Vitest (**не Jest**), Zod для окружения, Pino
- Nuxt 4 в режиме SPA, свой CSS, без библиотеки компонентов
- Два языка: словари в `@fatoff/contracts`, сервер шлёт `Message`, фразу
  собирает фронт (D-044)
- PDF — `pdfkit` со встроенными шрифтами, макет кодом (D-046)
- Оформление: Inter и JetBrains Mono локально, четыре гаммы × светлая и тёмная
  (D-031); цвет — на подложке и полоске, текст всегда чернилами (D-032)
- Порты: приложение 4090, Nuxt в разработке 4091, PostgreSQL 5482

Слои: `Controller → Service/Process → Repository → Entity`. Файлы в kebab-case,
идентификаторы в БД в snake_case, комментарии по-русски.

## Главные инварианты

1. **Сырьё — источник правды.** В базе лежат ответы YAZIO как есть; таблицы
   выгрузки считаются из них чистыми функциями при сборке файла. Не заводить
   «посчитанные» таблицы без крайней нужды (D-003).
2. **Экспорт не ходит в сеть** (D-010). Два прогона на тех же данных обязаны
   давать одинаковый файл — на это есть тест.
3. **Нутриенты YAZIO — на одну базовую единицу**, не на 100 г. Продукт
   умножается на `amount`, рецепт — на число порций, быстрая запись не
   масштабируется вовсе.
4. **Отсутствие значения ≠ ноль.** YAZIO не присылает нутриент, о котором не
   знает. Пустая ячейка и ноль в JSON/TOON различаются; в CSV — нет.
5. **Сбой одного запроса не роняет синхронизацию** — он становится строкой в
   `sync_warning`. Роняют только неверные учётные данные и отказ детектора
   изменений.
6. **Сверка с итогами YAZIO** — самая дешёвая проверка правильности всей
   выгрузки. Если она начала массово ругаться, сломалась арифметика, а не YAZIO.

## Ветки и окружения

**Правило, купленное дорого.** На порту 4090 крутится рабочий сервис — им
пользуются. Три ветки — три окружения, и они не пересекаются (D-043, D-057):

| ветка | что это | порт | база | как поднимается |
|---|---|---|---|---|
| `main` | прод | 4090 | `fatoff` в `fatoff-postgresql` (5482) | `pnpm db:up && pnpm docker:up` |
| `develop` | общая проверка | 4092 | `fatoff` в `fatoff-develop-postgresql` (5483) | `pnpm develop:up` |
| `feature/*` | своя работа | 4290 API, 4291 фронт | `fatoff_dev` в базе develop (5483) | `pnpm run dev` |

У каждого окружения свои контейнеры, свой том и своя сеть. Фича-ветки в докер не
уезжают вовсе: их запускают локально, и локальный фронт слушает `0.0.0.0` —
работу видно с телефона по адресу `http://<ip-машины>:4291`.

**Порядок, нарушать который нельзя (D-069):**

1. работа идёт в ветке `feature/<что-делаем>` от `develop`;
2. показывается человеку **из этой же ветки**, ссылкой на локальный контур;
3. в `develop` уезжает только после его согласия;
4. в `main` — только `develop` и только с отдельного согласия.

Показать работу — значит дать ссылку на **свою ветку**, а не слить и показать
develop. Слияние без спроса — не ускорение, а лишение человека решения, которое
принимает он.

Порядок проверяется хуками, а не памятью (D-059, D-069): прямой коммит в `main`
**и в `develop`** запрещён, в `main` сливается только `develop`, в `develop` —
только ветки задач, а согласие передаётся явно:

```bash
APPROVED_BY="кто одобрил" git merge --no-ff feature/<что-делаем>
```

Подставлять туда что попало, не спросив, — то же самое, что слить без спроса.
После слияния контур **пересобирается и перезапускается сам**. Ускоренное
слияние выключено (`merge.ff=false`) — иначе хук не запустится и правило
обойдётся молча.

Прод и develop делят только образ, собираемый из одного `Dockerfile`. Базы —
разные процессы на разных портах: неудачная миграция на develop физически не
может достать до прода.

В `.env` лежат настройки **локальной работы**, и compose подставляет оттуда
переменные. Поэтому подключение к базе в обоих compose-файлах записано числами,
а не через `${...}`: иначе окружение уехало бы на чужую базу.

Останавливать прод-контейнер, переименовывать под ним базу, применять к рабочей
базе незаконченные миграции — нельзя. В `main` уезжает только то, что прошло
`develop`.

## Репозиторий публичный

`git` настроен на публичный репозиторий, и это меняет требования к тому, что
попадает в коммит (D-058):

- **никаких секретов**: `.env`, `secrets/`, ключи, токены;
- **никаких чужих данных**: выгрузка Apple Health, дампы базы, собранные
  выгрузки, дневник питания в любом виде;
- **никаких опознающих следов**: почты, имена, живые замеры тела. В документах и
  тестах стоят условные значения, и они обязаны такими оставаться.

Проверяет это `scripts/scan-secrets.mjs`, который зовёт хук `.githooks/pre-commit`.
В новом клоне хук включается один раз:

```bash
git config core.hooksPath .githooks
```

Проверить весь репозиторий руками — `pnpm scan`; у самой проверки есть тесты
(`pnpm scan:test`), и они входят в `pnpm test`.

Порт для разработки выбирается не наугад: 4190 и ещё полсотни номеров стоят в
списке заблокированных портов спецификации fetch — браузер и `fetch` в Node
отказываются к ним ходить с невнятным «bad port».

И ещё: искать процесс по имени через `pkill -f` нельзя — под маску попадает сама
оболочка, из которой идёт работа. PID берётся из `ss -lptn 'sport = :4290'`.

## Команды

```bash
pnpm --filter @fatoff/api run dev               # backend разработки :4290
pnpm --filter @fatoff/web run dev               # фронт разработки :4291
pnpm test                                   # все тесты
pnpm --filter @fatoff/api run migration:create  # миграция из сущностей
YAZIO_EMAIL=… YAZIO_PASSWORD=… pnpm --filter @fatoff/api run check:yazio

pnpm --filter @fatoff/api run show:plan             # нормы, пул и неделя по живым данным

# прогон интерфейса в браузере: раскрытие дня, сборка режима, оба языка
# первый раз: pnpm exec playwright install chromium
# BASE по умолчанию :4291 — прогонять по разработке, а не по проду
ACCOUNT=<uuid> SHOTS=/tmp/shots pnpm --filter @fatoff/web run check:ui

pnpm scan           # весь репозиторий на секреты и чужие данные
pnpm scan:test      # тесты самой проверки

pnpm db:up          # только база прода, порт 5482 (обычно не нужно: docker:up поднимает обе)
pnpm docker:up      # выкатка прода (main): сборка образа и запуск на 4090
pnpm docker:logs    # логи прода

pnpm develop:up     # окружение develop целиком: база 5483 и сервис 4092
pnpm develop:down   # остановить его
pnpm develop:logs   # логи develop
```

Локальная работа и тесты ходят в базу **develop** (5483): прод не делит с ними
даже процесс базы.

Интеграционные тесты поднимают базы `fatoff_test_<файл>` и подставной сервер
YAZIO. Сеть им не нужна, но PostgreSQL нужен.

## Инварианты Apple Health

7. **Файл выгрузки — источник правды**, база хранит свёртку (D-020). Пересчёт —
   это повторный импорт: 2 ГБ за 21 секунду.
8. **Источники не складываются.** Часы и телефон меряют одно и то же независимо;
   на каждый день и тип берётся один источник (D-021).
9. **Питание из Health — это сам YAZIO**, а не второй источник (D-022).
10. **Ночь помечается датой пробуждения** (D-023).
11. **Расписания — у каждого аккаунта свои** (D-063): и синхронизация YAZIO, и
    проверка папки Drive. Общего расписания на всех нет. Целиком выключаются
    переменной `SCHEDULES_ENABLED` — на develop она `false`, иначе он ходил бы
    в YAZIO вторым экземпляром за теми же данными.
12. **Выгрузка может приехать сама** — из папки Google Drive, по расписанию или
    кнопкой (D-060). Что это выгрузка, решает содержимое; уже загруженный файл
    узнаётся по контрольной сумме и второй раз не разбирается.

## Инварианты дня и генератора

11. **Настройки генератора описаны один раз** — в `PLANNER_SETTINGS` (D-027).
    Оттуда интерфейс строит форму, оттуда же сервер берёт границы. Новая
    настройка добавляется записью в справочник, а не тремя правками.
12. **Тренировки расставляются до подбора еды** (D-030), но целевую калорийность
    больше не двигают: все дни плана одинаковы (D-074). Прибавка за тренировку
    осталась настройкой и выключена по умолчанию; проверка энергодоступности
    работает как работала.
13. **Одно зерно — один и тот же план.** Случайность заходит только через зерно
    и хранится вместе с планом; на это есть тест.
14. **Генератор молчит только когда сошлось.** Не уложился в допуск, не набрал
    белок или клетчатку — говорит прямо, а не отдаёт лучший из неподходящих.
15. **Составляющая оценки без данных выпадает из знаменателя**, а не даёт ноль
    (D-028). Низкая энергодоступность — отдельный флаг, а не штраф (D-029).
16. **Меню собирается комплектами** — приёмами пищи из её дневника, взятыми
    целиком (D-073). Состав не трогается, размер подгоняется одним коэффициентом
    на весь комплект. Завтрак — только из завтраков, обед и ужин делят один
    каталог, перекус при своём; правило описано один раз, в `MEAL_SOURCES`.
    Поблюдная сборка (D-026) осталась запасным путём: каталог пуст или блюдо
    закреплено руками. Пул сужается периодом дневника или отмеченным набором.
17. **Перекус выбирается первым и по своему правилу** (D-074): самый лёгкий из
    её перекусов, без цели по калориям. Остаток дня делят основные приёмы, и
    делят по очереди — недобор завтрака достаётся обеду.
18. **Правка готового плана пересчитывается на сервере** (D-034). Второй копии
    арифметики в браузере нет — она бы разошлась с первой.
19. **Закреплённое блюдо генератор не трогает**: подбор начинается с него и
    добирает остальное вокруг.

## Инварианты двух языков

20. **Сервер не сочиняет фраз** (D-044). Всё, что рождается на сервере, едет как
    `Message = { code, params }`; словарь один на интерфейс и на PDF.
21. **Справочник несёт обе версии рядом** — `Text = { ru, en }`. Добавить
    настройку или поле — по-прежнему одна запись, а не запись плюс две правки
    словарей.
22. **Забытый перевод — не ошибка, а тихая русская строка на английском экране.**
    Поэтому его ловят тесты и прогон в браузере (D-045), а не глаза.
23. **PDF воспроизводим** (D-046): дата сборки передаётся снаружи и идёт в
    метаданные, иначе два прогона дают разные байты.
24. **На листе у каждого числа есть подпись** (D-050). Экранная плотность на
    бумаге не читается: навести мышь некуда.
25. **Метки выбираются из заведённых, а не набираются** (D-048). Переименование
    и удаление метки меняют все планы с ней разом.
26. **Почта — не имя аккаунта** (D-053). У аккаунта есть имя, оно правится с
    обзора; почта показывается мелко и обрезается.

## Грабли, на которые уже наступали

- `em.upsert` не заполняет первичный ключ из инициализатора свойства — `id`
  передаётся явно, а `onConflictMergeFields` перечисляется, иначе на конфликте
  перезаписался бы сам ключ.
- Частичная синхронизация (один датасет) не должна затирать соседние поля
  снимка дня: в `upsert` уходят только запрошенные поля.
- Токен из базы едет в HTTP-заголовок, а он обязан быть ASCII — испорченное
  значение отбрасывается, иначе выгрузка падает ошибкой кодировки.
- `.tsbuildinfo` лежит внутри `dist`, иначе `nest build` считает вывод
  актуальным и не эмитит ничего.
- **Обработчик прогресса нельзя вызывать без `await`** (D-024). Незавершённый
  сброс в базу пересчитывает снимок сущности, и следующие присваивания теряются
  молча — значения в памяти есть, в базе нет, ошибки никакой.
- `em.insertMany` и `em.upsert` не выполняют инициализатор свойства: `id`
  передаётся явно, иначе not-null.
- Именованные подстановки `:param` MikroORM не понимает — только позиционные `?`.
  Массив в `= any(?)` knex разворачивает в перечень параметров, поэтому список
  констант подставляется в текст запроса.
- Даты вводятся через `DateField`, а не `input type="date"` (D-042): нативный
  календарь рисует браузер, и он всегда чужой — по-английски и в своей гамме.
- Общие правила для полей и прочих элементов пишутся через `:where()` (D-039):
  без него `:not()` в селекторе весит как класс и перебивает ширины из
  компонентов — молча, только на узком экране.
- `.grow` в общем CSS — это `flex: 1` с нулевой основой: длинный заголовок в
  такой ячейке налезает на соседнюю. Для строк с несколькими колонками нужна
  сетка с явными долями, а не флекс.
- Одна настройка выводится дважды — в основных и внутри своей группы; `id`
  поля берётся из `useId()`, а не из ключа настройки, иначе на странице два
  одинаковых `id` и подпись ведёт не туда.
- Плашка `.chip` внутри колонки-флекса растягивается на всю ширину, если не
  задать `align-self`. Пилюля во всю строку выглядит как ошибка вёрстки.
- Новый цвет в палитре добавляется одной строкой в блок гаммы, а не правкой
  подложек: они выводятся `color-mix` из того же цвета (D-031).
- Цели YAZIO берутся из последнего дня, где ключ калорийности правда есть:
  `goals is not null` пропускает пустой объект `{}`, который синхронизация
  кладёт на дни без целей.
- Вложенный DTO, объявленный ниже того, кто на него ссылается, роняет приложение
  на старте: `emitDecoratorMetadata` берёт класс в момент декорирования поля
  (D-036). `tsc` при этом молчит.
- Доля жира в Apple Health хранится долей (`0.2987`), а не процентом; в YAZIO
  её может не быть вовсе — тогда считается оценка по индексу массы тела и
  помечается оценкой.
- iOS пишет имя `экспорт.xml` внутри архива в UTF-8, но **не ставит флаг UTF-8**
  (бит 11). По стандарту это CP437, и любой честный читатель получает
  `╤ì╨║╤ü╨┐╨╛╤Ç╤é.xml`. Поэтому zip открывается с `decodeStrings: false`, а имя
  разбирается как UTF-8 самим сервисом.
- Путь к ключу сервисного аккаунта считается от каталога запуска: в разработке
  это `apps/api` (поэтому `../../secrets/…`), в контейнере — `/app/apps/api`,
  а ключ смонтирован в `/app/secrets`, поэтому там путь абсолютный.
- Удалённая миграция остаётся в `dist` скомпилированной, и `DB_AUTO_MIGRATE`
  применяет её снова — приложение падает на `column already exists`. Вместе с
  исходником убирается и `apps/api/dist/database/migrations/<имя>.js`.
- Общий пакет собирается в двух форматах (D-025): фронт — ESM, backend —
  CommonJS. Относительные импорты в нём пишутся с расширением `.js`.
- `pdfkit` добавляет страницу на любую запись за нижним полем, поэтому
  колонтитул печатается с обнулённым полем (D-051). Иначе в конце файла пустой
  лист — и виден он только в готовом файле.
- Заголовком страницы аккаунта бывает почта: без `overflow-wrap: anywhere` она
  делает страницу шире экрана, и телефон показывает всё уменьшенным (D-052). На
  мониторе это не воспроизводится вовсе.
- «Страница не едет вбок» ≠ «нет боковой прокрутки» (D-056). Ехать может кусок
  внутри: меню, вкладки, формула. Проверка теперь смотрит и на них, исключая
  `.table-wrap`.
- `minmax(17rem, 1fr)` в сетке не сжимается ниже 17rem и торчит наружу на
  экране в 320 пикселей. Пишется `minmax(min(17rem, 100%), 1fr)`.
- Прогон в браузере создаёт план и метку и убирает их за собой. `BASE` по
  умолчанию — разработка: направив прогон на прод, оставишь там мусор.
- Имя аккаунта и названия планов пишет пользовательница: поиск непереведённого
  текста их пропускает, иначе имя аккаунта на английском экране считается забытым
  переводом.
- Два флажка, из которых один включает другой, — это состояние, которое ничего
  не значит (D-055). Такой выбор делается переключателем.
- Страницы вне аккаунта (`/`, `/exports`, `/login`, `/accounts/new`, `/fields`)
  прожили без перевода дольше всех: обход по разделам их не видел. Теперь видит.
- Разделы страницы растут по одному и разъезжаются по механизмам вместо
  предметов (D-064, D-065). На «Синхронизации» сразу видно только свежесть
  данных и кнопку; всё остальное — под раскрытием. Состав разделов и то, что
  подробности спрятаны, закреплено прогоном по браузеру.
- Замечания заказчика приходят в документ на Google Drive и оттуда становятся задачами
  (D-071). Порядок описан скиллом `task-board`; статус задачи — в имени папки на Drive,
  текст — в документе, который создал человек. **Сервисный аккаунт не может владеть
  файлами**: квота нулевая, создание файла — 403. Папки создавать можно, чужие файлы
  править можно.
- Ход задачи уезжает заказчику в Telegram — `scripts/notify.mjs`, ровно четыре события:
  взял в работу, нужен ответ, можно смотреть, выкачено (D-076). Пятого события нет
  намеренно: группа, где каждый день пять сообщений ни о чём, перестаёт читаться. Порядок
  — документ, статус, оповещение. У ботов включён режим приватности, поэтому номер группы
  добывается командой с упоминанием бота в ней самой.
- Документ задачи пишется **в HTML** и заливается как HTML: простым текстом Google делает
  документ без единого заголовка (D-077). Образец оформления — документ задачи T-06.
- Документация обновляется в той же ветке, что и код: решение — в `DECISIONS.md`, состав
  экранов — в `ARCHITECTURE.md`, видимое при запуске — в `README.md`, грабли — сюда.
  Задача без этого не готова.
- Демо-аккаунт (D-068) наполняет базу теми же таблицами, что и настоящая
  выгрузка, и считается тем же кодом. Появится соблазн ветки «если демо» —
  значит, что-то пошло не туда: демо обязано показывать этот сервис, а не
  другой. Вес в нём выводится из баланса дня, а не рисуется кривой: разойдясь
  здесь, генератор начнёт врать в числах, которые сам же показывает.
- Демо, где каждый день зелёный, ничего не демонстрирует. Разброс оценок —
  такая же часть задачи, как непустые страницы, и он проверяется прогоном в
  браузере.
- Навигация — одна полоса (D-067): главное видно, остальное под «Ещё» и
  шестерёнкой, на телефоне разделы схлопываются под текущий. Кнопки «назад»
  нет; свойство `back` у `PageHead` осталось пустышкой ради страниц, которые
  его передают.
- Имя класса из одного слова (`sections`, `tabs`) почти наверняка уже занято
  другой страницей: `scoped`-стили не столкнутся, а прогон в браузере найдёт по
  такому селектору два разных элемента и упадёт на «strict mode violation».
  Классы новых общих компонентов — с приставкой (`bar__sections`).
- Ширина телефона в прогоне — 360 пикселей, а не 390: на 390 длинное название
  раздела ещё умещалось, на 360 выталкивало шестерёнку за край. Узкая ширина
  ловит строго больше.
- `locator.count()` считает и скрытые элементы. Кнопка, у которой класс
  подсветки стоит всегда, а показывается она только на телефоне, ломала счёт
  «подсвечен ровно один»: считать надо внутри видимой группы.
- `pnpm typecheck` в вебе падает не от правок: `nuxt typecheck` требует
  `vue-tsc`, а его нет в зависимостях. Гейт для веба — `pnpm build`.
- **`git checkout <файл>` возвращает файл из индекса, а не «как было минуту назад».**
  Незастейдженные правки при этом исчезают без предупреждения. Наступил на это,
  когда временно ломал код, чтобы проверить, ловит ли новая проверка поломку:
  откат «сломанного» снёс заодно всю работу. Правильный порядок — сначала
  `git add`, потом ломать, потом `git checkout`; или ломать копией файла.
- **Проверку новой проверки делай на копии.** Убедиться, что она падает на старом
  поведении, обязательно — но не ценой работы.
- `git stash` уносит и правки скрипта, и правки разметки: собрав разметку из
  «чистого» файла и удалив стэш, теряешь то, что было в скрипте. Разметка тогда
  ссылается на несуществующие переменные и молча показывает «ещё ни разу».
- Задача по расписанию живёт вне запроса, поэтому `RequestContext.create(em, …)`
  обязателен: сервисы работают через внедрённый `EntityManager`, и без контекста
  падают с «Using global EntityManager instance methods». Свой `fork()` не
  помогает — он для этой задачи, а не для того, кого она зовёт. Тест на голом
  классе этого не ловит: там `EntityManager` передают руками уже разветвлённым.
- Замена по якорю в скрипте молча делает ничего, если якорь успел измениться:
  два блока проверки я считал добавленными, а их не было. После правки файла
  скриптом — `git diff --stat`, а не «наверное, вставилось».
- Массовая замена русских строк на ключи регулярками съедает соседний текст:
  короткая строка вроде «Сколько она тратит» встречается внутри длинного абзаца.
  Многострочные куски заменяются по индексу блока, а не поиском подстроки.
- `pdfkit` без `info.CreationDate` ставит туда «сейчас» — файл перестаёт быть
  воспроизводимым, и тест на два одинаковых прогона падает без видимой причины.
- Единица нутриента и группа хранятся кодом (`kcal`, `minerals`), а подпись
  собирает интерфейс: русское «мкг» в типе означало бы, что английский экран
  показывает русскую единицу.
- **Внутри комплекта добрать нечего.** Приём берётся целиком, поэтому доводка по
  клетчатке умеет только одно — заменить приём на другой. Раньше хватало одного
  такого хода на день; теперь доводка идёт по всем основным приёмам, начиная с
  самого провального, иначе клетчатка проседает до единиц граммов.
- Синтетическая фикстура интеграционных тестов **не содержит перекусов вовсе**, и
  ни одно её блюдо не привязано к `snack`. Проверка «каждый приём взят комплектом»
  на ней падает не от поломки: перекус собирать не из чего. Проверять надо
  основные приёмы, а правило перекуса — модульным тестом.
- `scripts/show-plan.mjs` печатал `undefined` вместо названий приёмов и
  `[object Object]` вместо замечаний: он просил `meal.title` и склеивал `Message`
  строкой. Сервер фраз не сочиняет (D-044) — в отладочном выводе печатается ключ
  и `params`, а не подпись.
- **«У меня не воспроизводится» может значить «у меня другой браузер».** Клик по дню
  уезжал на сотни пикселей только там, где не работает scroll anchoring: Chrome такой
  переезд сглаживает сам, Safari на телефоне нет (D-075). Проверка, написанная в Chrome,
  проходила бы всегда — поэтому в прогоне `overflow-anchor` выключается намеренно.
- Раскрыт может быть только один день, поэтому клик по нижнему дню **убирает содержимое
  выше пальца**. Любое раскрытие, где соседний блок схлопывается, обязано удерживать
  нажатую строку: `keepInPlace` из `useKeepInPlace.ts`.
- Порог из кода, который видит человек, подставляется в текст, а не пишется в нём
  словами: «не меньше {count}» с подстановкой `FULL_DAY_MEALS` (D-078). Иначе правило
  меняют в одном месте, а на экране остаётся прежнее число — и никто не замечает.
- Правка синтетической фикстуры отзывается в чужих тестах: добавив одну запись в дневник,
  сломал три счётчика в `browse.spec.ts`. Числа там приколочены намеренно, так что после
  правки фикстуры — прогонять весь набор, а не только свой файл.
- **Номер решения перед употреблением проверять.** `D-072` был занят соседней
  задачей, а в комментариях кода он уже стоял. Перед тем как ссылаться на новый
  номер — `grep -oE '^## D-[0-9]+' docs/DECISIONS.md | tail -1`.
